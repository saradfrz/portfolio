Featured

Bitcoin Data Pipeline Benchmark — Snowflake

An end-to-end Snowflake data platform processing over one billion historical BTCUSDT trade records. One implementation of a cross-platform engineering benchmark comparing cloud data warehouse and lakehouse architectures.

The platform implements historical Binance trade ingestion using Python, Parquet staging, dbt SQL transformations, and dependency-driven orchestration using Snowflake Tasks. Medallion Architecture separates raw ingestion, normalized trades and daily summaries, and curated analytical data products. Full-refresh and incremental execution paths support historical backfills, data quality validation, and retention management. Financial analytics include daily OHLC summaries in Silver and 50-day and 200-day simple moving averages, cumulative volume delta (CVD), and volume-weighted average price (VWAP) in Gold. The implementation explores incremental processing, orchestration dependencies, data consistency, and warehouse architecture trade-offs.

Bitcoin Data Pipeline Benchmark — Databricks

An end-to-end lakehouse implementation processing over one billion historical BTCUSDT trade records using Apache Spark, Delta Lake, and Databricks. The distributed processing counterpart to the Snowflake implementation of the same benchmark.

Python acquires historical Binance trade files and stores them in Unity Catalog Volumes. Auto Loader incrementally ingests source files into Delta Lake using Structured Streaming and checkpoints. Spark transformations implement Bronze, Silver, and Gold layers, with Databricks Workflows coordinating execution dependencies. The platform supports full-refresh and incremental processing, historical backfills, and data quality validation. Silver contains normalized trades and daily OHLC summaries; Gold provides 50-day and 200-day simple moving averages, cumulative volume delta (CVD), and volume-weighted average price (VWAP). The implementation explores distributed processing, incremental file ingestion, checkpoint-based recovery, and lakehouse architecture trade-offs.

Planning

Real-Time Financial Data Pipeline — Kafka & Azure

A planned event-driven data platform for live cryptocurrency market events using Apache Kafka on Azure. Designed as a reproducible, time-bounded experiment measuring streaming performance and cloud infrastructure costs.

The proposed architecture will consume public cryptocurrency trade events from the Coinbase WebSocket API through a Python producer and publish them to Apache Kafka on Azure infrastructure. A consumer will validate, normalize, and aggregate events into windowed price, volume, and volatility metrics, with raw events and analytical outputs persisted to Azure Blob Storage. Terraform will automate provisioning and teardown, and Docker will package application components. A controlled 10-minute streaming workload will evaluate throughput, end-to-end latency, consumer lag, resource utilization, and estimated versus actual cloud costs across the deployment lifecycle. Planned experiments include consumer recovery, duplicate handling, event-time processing, and delivery guarantees. The project will operate within the constraints of Azure for Students.

Planning

Containerized Batch Data Platform — Airflow, dbt & Kubernetes

A planned batch data platform for historical U.S. Treasury yield curve data using Apache Airflow, dbt, DuckDB, and Kubernetes on AWS. Designed to demonstrate reproducible batch execution, modular transformations, and resource-efficient infrastructure.

The proposed platform will ingest public U.S. Treasury yield curve data with Python and preserve source CSV files in an Amazon S3 Bronze layer. Apache Airflow will orchestrate containerized ingestion, transformation, validation, and publication tasks through Kubernetes. dbt and DuckDB will implement SQL transformations and write normalized Silver datasets and curated Gold data products as Parquet files in S3. Analytical models will calculate yield spreads, maturity comparisons, rolling interest rate averages, and inversion indicators. A lightweight Kubernetes deployment on Amazon EC2 will support the experiment without requiring a managed Kubernetes control plane. Engineering objectives include deterministic execution, idempotency, dependency management, data quality, and reproducible deployments within AWS educational environment constraints. The architecture is deliberately designed to explore orchestration and container scheduling rather than minimize complexity for this small dataset.
